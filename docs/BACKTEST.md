# Scoring backtest

Generated by `python main.py backtest --write`. Anchors every 30 days from 2024-10-19 to 2026-09-09; each scores sectors from the previous 60 days of signals and is compared with the distinct organisations per sector named on leak sites in the next 30 days. Victim data in the database runs from 2017-05-12 to 2026-10-09.

| CII designation only (baseline) | -0.254 | 0.115 |
| Random (expected) | 0.0 | 0.214 |

Anchors evaluated: 24. The model's rank correlation beat the recent-victims baseline at 4 of them. Anchors where all six components had data: 0.

## What this can and cannot show

- The outcome is leak-site postings. Organisations that pay quietly never appear, so the test measures agreement with a biased sample, not with all incidents.
- Most anchors only had victim history: the exploit, infrastructure, pressure and exposure components have no stored history before late August 2026, so at those anchors the model reduces to impact plus criticality. Those four components are untested until scheduled collection builds history (the daily GitHub Actions run does this); re-run this backtest as it accumulates.
- 14 sectors and roughly 10-30 victims a month make every anchor noisy; read the averages, not single rows.
